Secrets-port conformance — every [cuora_secret::Secrets] impl must satisfy the same contract. Unlike vault_conformance! this is a plain fn (not a macro): stores carry their own isolation (service namespace, file path, stub binary), so the caller constructs a fresh store and calls secrets::conformance from however many #[test]s it wants — typically one, gated on available() where the backend needs a live service.

Values here are fake by rule — no real secret ever appears in a test fixture.
